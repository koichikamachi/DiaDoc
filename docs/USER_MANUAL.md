# DiaDoc 取扱説明書（改善版）
Sep 28, 2026 · @KoichiKamachi

DiaDoc は、三人の担当者（Radar・Growth・Rebuild）が同じ会社を別々の立場から論じ、ディレクター（Judge）が審査し、資金の計算と段階の切り替えはプログラムが決める経営診断の道具です。この説明書は、9月後半に加えた改善を含めて、画面の使い方を順に説明します。

## 1. 画面の全体像
画面は、左のサイドバーと、右側の4つのタブでできています。論争はいちばん左のタブ「論争コックピット」で進めます。

| 場所 | ここでできること |
| :--- | :--- |
| **サイドバー** | 対象企業と分析回次を選ぶ。新しい会社・新しい回次を開く。論争のやり直し。「実質BSで見る」の切り替え。議論ログの CSV とレポートの保存 |
| **論争コックピット** | 左の「資料ドック」、中央の「対話タイムライン」、右の「ライブ・メトリクス」の3つの枠で論争を進める |
| **財務・4P突合マトリクス** | 指標と比率の計算式・出典、検算の結果、貸借対照表の図、実質化の調整 |
| **意思決定ツリー** | 論争とともに育つツリー、道の比較、採択の記録 |
| **回次の比較** | 同じ会社の分析回次の結論を横に並べる |

### 論争コックピットの3つの枠の役割
- **資料ドック（左）：** 診断ミッション、投入済みの資料、追加インプット（資料の追加）。
- **対話タイムライン（中央）：** 担当者の発言、Judge の審査、フェーズの判定、人間の介入が時系列で並びます。上下に「1手進める」などのボタンがあります。
- **ライブ・メトリクス（右）：** 売上高・営業利益率・実質ROA・手許現預金・借入残高・残余月数、ボトルネックと因果関係、提案の採否ステータス。論争が進むたびに更新されます。

### 登場人物の役割
担当者は、同じ案件を受け持つ同僚コンサルタントとして表示されます。色は区別の補助で、必ず名前と肩書が添えてあります。

| 表示名 | 役割 |
| :--- | :--- |
| **Analyst Radar** | データ解析・客観調査（リサーチ担当） |
| **Prof. Growth** | 現場改善・事業成長（オペレーション担当） |
| **Dr. Rebuild** | 事業再生・財務規律（外科手術担当） |
| **Moderator Judge** | 案件統括・進行裁定（ディレクター）。審査と比較はするが、道を選ぶことはしない |
| **支援担当者** | 人間（操作者）。介入と確定はこの名前で記録される |

## 2. 対象会社と分析回次
論争は「対象会社」ごとに、「分析回次（Run）」という単位で記録します。決算書が変われば回次を改め、同じ決算書の上で議論を深めるときは同じ回次のまま進めます。

### 新しい会社を登録する
1. サイドバーの「＋ 新しい対象会社」を押し、会社名・業種・診断ミッションを入れて「作成する」を押します。実在の会社でなければ「架空モデル」に印をつけます。
2. 中身が空の「第1次分析」ができます。資料ドックの「追加インプット」で財務書類を投入します。
3. 検算を通れば、その数字がこの回次の財務データになります（空の第1次分析だけは、新しい回次を開かずにそのまま入ります）。検算で止まったときは「一致しなかった項目」に、どの合計がいくら合わなかったかが出ます。

### 資料を足すときの規則
| 資料の種類 | どうなるか |
| :--- | :--- |
| **定性資料（ヒアリングメモなど）** | 今の回次に加わり、論争はそのまま続きます。担当者は次の手から出典として引用できます |
| **財務書類（決算書、有報など）** | 検算したうえで、新しい回次を開いて最初から論じます。数字が変われば前提が変わるためです |

ファイル名に「決算書」「財務諸表」「有報」「FS」などが入っていれば、財務諸表として扱います。試験用の読み取り（モック）の結果は、財務データとしては採用しません。

### 回次を改める・やり直す
- **新しい回次：** 「＋ 新しい分析回次（Run）を開始」を押すと、いまの回次を凍結し、その状態を引き継いだ次の回次が開きます。凍結した回次は見るだけで、変えられません。
- **やり直し：** 「この回次の論争をやり直す」→「やり直す」で、論争の途中状態を消して最初から始めます。投入した資料と、入れた実質化の調整は残ります。

## 3. 論争を進める
論争は一手ずつ止まりながら進みます。止まっている間は、いつでも読み返したり介入したりできます。

### 進めるボタン
- **▶ 1手進める：** 次の一人が発言して止まります。タイムラインの下にも「▶ 次の1手（次：〇〇）」があり、読み終えた位置からそのまま押せます。
- **⏩ 次のラウンドへ：** いまのラウンドの残りをまとめて進めます。
- *※処理中（発言の生成や検算の最中）にボタンを重ねて押しても、二重には進みません。*

### 発言者を指名する
「次の発言者」の選択欄は、既定が「自動（通常順）」です。Radar・Growth・Rebuild のどれかを選んで進めると、その担当者が割り込んで話します。指名は一手ごとで、進めたあとは「自動」に戻ります。指名できるのは探索のフェーズだけです（トリアージ以降は順番が決まっています）。

### 介入する
タイムラインの下の「支援担当者介入」に書いて「介入する」を押します。例：「銀行は返済猶予に応じない見込み」「遊休地の売却は地元の反対で難しい」。
- **誰に答えさせるか：** 担当者を選ぶと、その人が順番を割り込んで次に答え、答えたあとは元の順番に戻ります。選ばなければ、次の発言者がこの介入を読んで答えます。
- **介入したらすぐ 1 手進める：** 印があれば、書き込んだ直後に返答が出ます。
- 介入は「条件」として扱われ、Judge の審査にはかかりません。担当者はその後の手で、介入を前提に議論します。

## 4. 診断ミッションから採択まで
論争は「診断ミッション」に向けて進み、探索→トリアージ→決着の順に段階が切り替わります。切り替えはプログラムが資金の計算から決め、Judge はそれを宣言するだけです。

### 診断ミッション
資料ドックのいちばん上に表示され、全担当者に共通の討議目的になります。「ミッションを変える」を開き、「主訴の型」から選ぶか自由に書いて「このミッションで進める」を押します。論争の途中で変えると、介入として記録に残ります。

### 発言の審査
発言はまずプログラムが形式を審査し、次に Judge が中身を審査します。Judge は判定を厳しくすることはできても、緩めることはできません。
1. 出典が「引用できる資料」にあること（資料名と頁）。
2. 改善案には「因果ブリッジ」＝どの勘定科目が、いくら、何か月後から資金に効くか。金額と経路のない定性論は審理しません。
3. 同じ話の繰り返しは差し戻し。判定は「通過」「差し戻し」「退け」の3つです。

### 4つの改善レバー
改善案は、勘定科目から次の4つのレバーに自動で振り分けられます。Growth は、資金の不足が埋まらないかぎり、4つすべてを試し尽くすよう求められます。

| レバー | 主な科目 |
| :--- | :--- |
| **売上・粗利** | 売上高、営業外の収益 |
| **原価・現場** | 材料費・労務費・経費、仕入 |
| **固定費・販管費** | 販管費の内訳、支払利息など |
| **資産売却・BS** | 遊休資産の売却、在庫・売掛金の圧縮など、貸借対照表の科目 |

### 段階の切り替わり
| 段階 | 誰が何をするか | 次に進む条件 |
| :--- | :--- | :--- |
| **探索** | Radar・Growth・Rebuild が調査と改善案を出し、Judge が審査する | 4レバーを試しても資金の不足が残る、または上限のラウンドに達した |
| **トリアージ** | Rebuild だけが「宣告」でき、道を 2 つ以上、それぞれ残すもの・捨てるもの・前提条件つきで示す | 宣告が審査を通った |
| **決着** | Judge が道を同じ物差しで比べる（選ばない） | — |

*※切り替えの基準値（不足の点検は第2ラウンド、膠着は2回、上限は第4ラウンド）は、現在仮置きです。*

### 道の比較と採択の記録
「意思決定ツリー」タブの「Level 0 の道の比較」に、雇用・資金繰り・債権者に求めること・道筋がつくまでの月数・リスクが並びます。道筋がつくまでの月数が残余月数に収まるか（✓✕）はプログラムが判定します。比較より前に閉じた古い回次では、「宣告された道を比べる（Judge）」で後から比較できます。

どの道を採るかは、経営者や金融機関との協議で人間が決めます。論争が閉じたあと、「採る道」と「理由・条件（任意）」を入れて「この道を採択として記録」を押します。採択は論争の中身を変えず、記録として残ります。

## 5. 財務・4P突合マトリクス
論争の根拠になる数字を、計算式と出典の頁つきで確かめるタブです。ここに出る数字は、そのまま論争の根拠に使えます。

### 指標（上段のタイル）
- **全社共通：** 売上高・営業利益率・総資産・自己資本比率・有利子負債・手許現預金・営業利益ROA・残余月数（改善前）。
- **会社固有：** 受取配当金がある会社には「受取配当依存」、商品の仕入がある会社には「商品仕入高比率」を加えます。
- 各タイルの `?` に、計算式と内訳（科目・金額・出典の頁）があります。小さな文字は前期比で、金額は増減率（例：+15.8%）、比率はポイント差（例：-0.4pt）です。
- 残余月数は「手元資金 ÷ 返済後の月間流出」です。簡易キャッシュフローは「経常利益 − 法人税等 ＋ 減価償却費」、返済は1年以内の約定返済（長期借入金・社債・リース債務）で計算します。

### 比率の突合と基礎数値
横棒グラフで対象企業と比較値を並べ、その下の「グラフの基礎数値と典拠」に、比率ごとの計算式、分子・分母の内訳、比較値の出典を表にしています。比較値が仮置きのときは黄色の注意が出、斜線の棒で描かれます。仮置きの値は判断に使わないでください。

### 検算
「自動検算ステータス」は、読み取った数字どうしが財務諸表の中で辻褄が合っているかを確かめた結果です。例えば、流動資産の内訳の合計が流動資産合計に一致するか、販売費と一般管理費の合計が販管費合計に一致するか、です。「この検算は何をしているか」に平易な説明、「検算の明細」に項目ごとの結果があります。千円未満の切捨てによる小さな差は、許容範囲として一致に数えます。
右側の「データ請求（欠落科目アラート）」には、論争に必要なのに足りない科目と、その請求先が並びます。

## 6. 貸借対照表と実質化の調整
貸借対照表は、柱の高さが金額に比例する図で表します。実質の姿は「帳簿 ＋ 人が確かめて入れた調整」です。外からは分からない含み損益を、プログラムが推測で加えることはしません。

### 図の読み方
- 左の柱が資産（青）、右の柱が負債（オレンジ）と純資産（緑）です。資産は「現金預金・その他の流動資産・有形無形固定資産・投資その他の資産」、負債は「流動負債・固定負債」に分けて積みます。
- 仮払金や役員借入金なども、帳簿で計上されている区画のまま描きます。株式や土地は取得原価で計上されている前提です。
- 調整がないうちは「帳簿＝実質（調整なし）」の1組だけです。調整を入れると「名目（帳簿）」と「実質（調整後）」の2組が同じ目盛りで並びます。
- 斜線の部分が調整です。名目の列では「実質で除く分」、実質の列では「実質で加わる分」を表します。斜線を除いた土台は2つの列で同じ高さになるので、何が消え何が加わったかを見比べられます。
- 純資産がマイナスになると、緑の柱がゼロより下に「債務超過」として描かれます。
- 表示単位は金額の桁で決めます。総資産が10億円に届かないときは百万円、10億円以上なら億円です。

### 実質化で確かめたい科目
図の下に、実質の姿を出すために確かめるべき科目と、確かめることが並びます。帳簿に残高がある科目だけが出ます。

| 科目 | 確かめること |
| :--- | :--- |
| **投資有価証券** | 取得原価の前提。銘柄と時価が分かれば、含み益（＋）・含み損（−）を調整として入れる |
| **関係会社株式** | 関係会社の財政状態が悪ければ、実質価値との差（−）を入れる |
| **土地** | 路線価や鑑定で時価が分かれば、含み損益を入れる |
| **仮払金** | 中身と精算の見込みを確かめる。資産性がなければ減額（−）を入れる |
| **保険積立金** | 帳簿の額と解約返戻金の差を確かめ、差額を入れる |
| **役員借入金** | 負債のまま扱う。資本とみなすのは金融機関の見方で、実際には劣後化や債務免除などの手続きが要る。手続きがあった時点で調整を入れる |

*※上場会社のように、決算書に評価差額金が載っている（株式が時価評価済みの）会社だけは、開示された数字から含み益を除く調整をプログラムが自動で入れます。一覧には「決算書の開示から自動」と表示されます。*

### 調整を入れる（介入）
1. 「調整を入れる（介入）」の「科目」で、確かめた科目を選びます。一覧にない科目は「その他の科目」を選び、科目名と区画を入れます。
2. 「増減額（千円）」を入れます。資産も負債も、増やすなら＋、減らすなら−です。例：株式の含み益300万円なら「3000」、仮払金を全額落とすなら「-2300」。
3. 「根拠」に、何で確かめたかを書きます（証券会社の残高報告書、社長への聞き取りなど）。
4. 「調整を入れて論争に伝える」を押します。

押すと、次の3つが同時に起きます：
- 図の実質の列と、実質の指標（自己資本比率・実質ROA など）が変わる。調整の差額はすべて純資産に効きます。
- 対話タイムラインに、支援担当者の介入として記録される。
- 担当者には以後毎回、実質の貸借対照表と入っている調整が渡る。古い発言が流れても、調整は前提として残ります。

**注意点：**
- 税効果は考慮しません。入力した額がそのまま純資産に効きます。
- 調整は資金（残余月数など）の計算を変えません。含み益は売らなければ現金にならないためです。売却で資金を作る案は、論争の中で「資産売却・BS」の改善案として出してください。
- 入れた調整は「入っている調整」に並び、「取り消す」で消せます。取り消しも介入として記録されます。
- 調整は回次ごとに保存されます。定性資料だけを足した回次には引き継がれ、決算書を差し替えた新しい回次には引き継がれません。
- サイドバーの「実質BSで見る」をオンにすると、指標のタイルと比率が調整後の数字で表示されます。

## 7. 論争から育つ意思決定ツリー
「意思決定ツリー」タブのいちばん上のツリーは、論争が一手進むたびにプログラムが状態から描き直します。枝は増えるだけで、減ることはありません。左から右へ読みます。
- **根：** 診断ミッション。今が第何ラウンドのどの段階かも添えています。
- **枝：** 4つの改善レバー。まだ提案がないレバーは点線です。
- **葉：** Growth と Rebuild の提案。審査と資金の時間軸で見た結果、資金への効果、何か月後から効くかを載せています。棄却された提案には理由も書いています。
- **複数のレバーにまたがる提案：** 関係するレバーそれぞれから枝が伸びます。金額の裏付けがない定性論はどのレバーにもつかず、根から直接出ます。
- **支援担当者が置いた前提：** 支援担当者の介入（直近3件）を付箋の形で、根から点線でつなぎます。採択の記録は前提ではなく結論なので、ここには入れません。
- **トリアージ：** Rebuild の宣告が審査を通ると「Level 0 の道」の枝が生えます。道ごとに、残すもの・捨てるもの、道筋がつくまでの月数、資金が尽きる前か後かが出ます。採択を記録すると、その道が★で濃く塗られ、ほかの道は「不採択」になります。

ツリーの下には「Level 0 の道の比較」と「採択の記録」が続きます（4章）。論争と連動しない以前の固定のツリーは、最下部の「（参考）旧・静的ツリー」にしまってあります。

## 8. 資料を見る・回次を比べる・書き出す
### 資料の中身を見る
資料ドックの「投入済みの資料」で資料名を押すと、その資料を出典とする科目と頁の一覧が開きます。ヒアリングメモなどの文書は本文が表示されます。原本は「公開元で原本を開く」または「ファイルを保存」で確かめてください（PDF は画面の中では開かず、保存して見ます）。

### 回次を比べる
「回次の比較」タブで「比べる回次」を選ぶと、同じ会社の回次の結論が横に並びます。並ぶのは、診断ミッション、論争の進み具合、試した改善レバー、最終フェーズ、残余月数（改善前→改善後）、回収CFと必要CF、残りの不足、審査通過・時期内の改善案、宣告された道、採択された方針です。過去の回次は読み取り専用で開くので、比べても記録は変わりません。

### 書き出す
- **議論ログの CSV：** サイドバーの「📥 議論ログをCSV出力」、またはタイムライン上の「📥 CSV」。因果ブリッジごとに1行で、ラウンド・発言者・発言・科目・金額（千円）・所要月数・判定・残余月数・回収CF累計・時刻の12列です。Excel でそのまま開けます。
- **レポート：** サイドバーの「レポートを保存（Markdown）」。

## 9. 表示の読み方と制約
### 提案の状態
採否ステータスとツリーに出る状態は次のとおりです。どれも審査と資金の時間軸からプログラムが決めており、「採用」を意味するものはありません。採用は人間の「採択の記録」だけです。

| 記号 | 状態 | 意味 |
| :---: | :--- | :--- |
| **◎** | 審査通過・時期内 | 審査を通り、資金が尽きる前に効く |
| **◐** | 一部のみ間に合う | 資金が尽きる前に効くのは一部だけ |
| **◷** | 審査通過・時期外 | 審査は通ったが、効果が出るのは資金が尽きた後 |
| **×** | 棄却 | 審査で差し戻しまたは退け |
| **…** | 審理中 | Judge の審査前 |
| **✓✕** | 道の時期 | 道筋がつくまでの月数が残余月数に収まるか |
| **★** | 採択 | 人間が記録した道 |

### 知っておきたい制約
1. 出典は、資料名と頁が引用できる資料にあるかを確かめるだけです。その頁に本当にそう書いてあるかまでは確かめません。実際に、ヒアリングメモの数字を決算書の頁として引いた例がありました。大事な数字は資料のプレビューで確かめてください。
2. 段階の切り替えの基準値と、業種の比較値は仮置きです。
3. 資金の計算は簡易キャッシュフローによる近似です。月次の資金繰り表の代わりにはなりません。
4. 実質化の調整では税効果を考慮しません。
5. C002（窮境・金属プレス部品）は、対比のために作った架空の会社です。
6. サイドバー下部の「発言の生成」が「台本（モック）」のときは、決まった台本で動いています。実際の AI（Gemini）が発言するのは、設定で切り替えたときだけです。
